## Разбивка инфраструктуры на блоки управляемые Terraform и вручную


| Блок                                                                                                  | Управляется Terraform |
| ----------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| VM для каждой подсистемы                                                               | Да                             |
| Диски (например, под базы данных)                                               | Да                             |
| Виртуальная сеть (VPC)                                                                     | Да                             |
| Подсети, маршруты, Firewall                                                                | Да                             |
| Балансировщики нагрузки (Kong)                                                      |                                  |
| Секреты/переменные (Vault/SSM)                                                           | Да                             |
| Software system (Финтех система, Медицинская система, ИИ система) |                                  |
| Платформенные сервисы                                                                 |                                  |
| Аналитическая платформа (Apache Superset)                                           |                                  |
|                                                                                                           |                                  |

Принцип которым руководствовался - инфраструктура управляется Terraform, сервисы - (Ansible/docker/kubectl), так как в противном случае конфигурация Terraform становится сложной и избыточной. Опционально в Terraform можно разворачивать конфигурации. Это удобно, с  позиции версионирования. А разворачивать сервисы специализированными инструментами возможно более гибко, проще и быстрее.

**Обоснование конфигурации:**

Размер ВМ: 2 vCPU, 4 GB RAM — достаточно для тестового окружения.

Размер диска: 20 GB SSD, так как хранится только логика приложения и логи.

NAT включён, чтобы иметь доступ в интернет для установки обновлений и зависимостей.

Сеть и подсеть описаны декларативно в Terraform, чтобы воспроизводить окружение на любом аккаунте.


Декларативный подход (IaC) позволяет:

* повторно создавать окружение одной командой terraform apply;
* отслеживать изменения через Git;
* масштабировать, изменяя только конфигурацию;
* избежать ручных ошибок при настройке.


IaC делает инфраструктуру прозрачной и версионируемой, а Terraform — стандартный инструмент для таких задач, так как он:

* поддерживает разные провайдеры (AWS, Yandex, GCP, Azure);
* имеет декларативный синтаксис;
* позволяет использовать переменные и шаблоны для разных окружений (dev, prod).

Итог: выбрана базовая конфигурация, которая удовлетворяет текущим требованиям, но с возможностью роста и изменяемости благодаря IaC.
Для дальнейшего моделирования, желательно иметь профиль нагрузки, количество пользователей (их территориальное расположение), объем данных и какие отчеты требуется формировать, а также определить НФТ.
